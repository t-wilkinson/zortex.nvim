1. INTRODUCTION                                                 *zortex-intro*

zortex.nvim is a plain-text life-management system: notes are `.zortex`
files (a markdown dialect) that link to each other by structure,
`[Sourdough/#Method]` or `[P/#1.1 Kitchen shelves]`. Projects, areas,
objectives and the calendar are notes too. Notes live in `notes_dir`
(default `~/zortex`); `z/` holds resources and archives. The server
(`zortex serve`) shows them in a browser and runs the calendar's
notifications and the pomodoro (|zortex-server|).

Requires Neovim 0.10 or newer. Optional: snacks.nvim, telescope.nvim or
fzf-lua (pickers; `ui.picker`), blink.cmp or nvim-cmp (link completion).
|:checkhealth| zortex checks the setup.

The full documentation is in the repository:
    README.md          quickstart, features
    doc/Syntax.md      the note format (checked against the parser)
    doc/Server.md      running the server
    doc/Projects.md    projects and areas
    doc/Planning.md    areas, OKRs, reviews, XP (Mastery, seasons)

2. SETUP                                                        *zortex-setup*

With lazy.nvim: >lua
    { "t-wilkinson/zortex.nvim", config = function()
        require("zortex").setup({ notes_dir = "~/zortex" })
    end }
<
Options go to setup(): >lua
    require("zortex").setup({
      notes_dir = "~/zortex",
      keymaps = { prefix = "<leader>z" },
    })
<
setup() writes nothing. When key notes are missing (calendar, projects,
areas, okr, structure, inbox) it says so once; `:Zortex init` creates the
missing ones from short templates (|:Zortex|).

Notes open folded to their headings (`features.folding.level`): |zR| opens
every fold. A section marked `@fold` starts closed whenever the note is
shown, whatever its level.

==============================================================================
3. NOTES                                                        *zortex-notes*

A note starts with a header: `@@Name` lines (the first is the article name,
the rest aliases) and `@Tag` lines. The body has headings (`#`..`######`),
bold headings (`**Next steps:**`), labels (`Ideas:`), list items and tasks
(`- [ ] task @size(sm)`, `14:00 event`), attributes (`@p1`,
`@due(2026-10-20)`, `@area(4.1)`, `@spent(1h25m)`; short forms: `@a(4.1)`,
`@n(15)` for `@notify(15)`, `@sm`, `@90m` for `@dur(90m)`) and links. A
link's components narrow left to right: an article (or tag namespace like
`P`), then `#heading`, `:label`, `*bold`, `-item` or `%text`, each matched
by prefix, case-insensitively.

Special notes: projects.zortex (`@@P`; any note tagged `@P` is a project
too), areas.zortex (`@@A`), okr.zortex (`## 3M-2026-Q1 Title` objectives,
grouped under top-level headings, with `- KR1: [ ]` key results),
calendar.zortex (`YYYY-MM-DD:` days), structure.zortex (links to
everything), inbox.zortex.

5. CONFIGURATION                                               *zortex-config*

setup() merges your options over these defaults: >lua
    {
      notes_dir = vim.fn.expand("~/zortex/"),
      extension = ".zortex",
      debug = false,
      -- This machine's name in the synced folder (.z/xp_summary.<device>.json),
      -- so devices never write the same file; nil: the host name
      device = nil,

      -- Commands and keymaps are generated from zortex.actions (:Zortex lists them)
      commands = {
        prefix = "Zortex", -- :ZortexSearch, :ZortexReview, ...
      },
      keymaps = {
        enabled = true,
        prefix = "<leader>z",
        -- Per-action overrides by action id: a key, a list of keys, or false.
        -- e.g. { task_toggle = "t", search_articles = false, review = { "w", "R" } }
        mappings = {},
        -- which-key names for key prefixes (when which-key is installed):
        -- <prefix> is "Zortex", and a prefix like "x" of "xs" is named after
        -- its actions' group ("XP") unless set here. false skips one, or set
        -- groups = false to name none.
        groups = { C = "Calendar" },
      },

      core = {
        logger = {
          enabled = false,
          log_events = false,
          level = 3, -- TRACE, DEBUG, INFO, WARN, ERROR
          max_entries = 1000,
          performance_threshold = 16, -- Log operations taking > 16ms
        },
      },

      -- `zortex serve -data DIR` (app/), running on this computer or elsewhere:
      -- the web app, the calendar's notifications and the pomodoro clock (both
      -- sent through ntfy). With a base path the endpoint includes it, e.g.
      -- "https://zortex.home.lab/notes". false: notes only (no notifications,
      -- no pomodoro).
      server = {
        enabled = true,
        api_endpoint = "http://127.0.0.1:8090",
        api_key = nil, -- the server's -api-key / ZORTEX_API_KEY, if set
        user_id = "default",
        -- the web app's address for :ZortexPresent and <prefix>gX when it
        -- isn't api_endpoint
        -- (e.g. "https://zortex.home.lab/notes"); nil: api_endpoint
        web_url = nil,
      },

      features = {
        folding = {
          -- Notes open folded below this level: 1 shows the headings of a
          -- note (zo / zR open folds); 99 opens everything
          level = 1,
          include_empty_lines = true,
        },
        -- Links that resolve nowhere (and paths to missing files) as
        -- vim.diagnostic on their notes (]d / [d); severity "ERROR" | "WARN" |
        -- "INFO" | "HINT"
        diagnostics = { enabled = true, severity = "WARN" },
        -- J in a note drops what only starts a line: the joined line's
        -- "#"s, "-" (and "[ ]"), "1." or "> "; a label keeps its ":".
        -- gJ joins as written.
        join = { enabled = true },
        -- Calendar feeds: `zortex serve -feeds` writes each feed's events
        -- (a Cozi or Google calendar's iCal link) into
        -- z/feeds/<name>.zortex (doc/Server.md), and they show read-only in
        -- the calendar view, the planner and the agenda. Per-feed toggles:
        -- { cozi = false } hides one; false hides them all.
        calendar_feeds = {},
        -- <prefix>gX: links in the web app (server.web_url)
        web = {
          -- show them in the tab on this computer you focused last, when
          -- the server is enabled and one is open; false: a new tab
          reuse_tab = true,
        },
      },

      -- Notifications go through the server: every timed line of the calendar
      -- notifies at its time (@notify(15) adds one 15 minutes before,
      -- @notify(no) turns it off), and the server sends them, with the
      -- pomodoro's phase changes, through ntfy (its -ntfy-* flags). The alerts
      -- it raises also show in Neovim.
      notifications = {
        enabled = true, -- send the calendar's notifications to the server
        advance_minutes = 0, -- minutes before a timed line without @notify(...)
        days = 30, -- how many days ahead
        alerts = true, -- show the server's alerts in Neovim
        poll_seconds = 15, -- how often Neovim asks for them
      },

      ui = {
        -- Search, projects, calendar and follow-link pickers: "telescope",
        -- "snacks", "fzf_lua" or "select" (vim.ui.select). "auto": LazyVim's
        -- picker, else a snacks.picker you enabled, telescope, fzf-lua,
        -- snacks.picker, and vim.ui.select when none is installed.
        picker = "auto",

        -- Highlight groups: linked to your colorscheme by default.
        -- preset = "rose-pine" for a Rose Pine Moon palette; groups = { ZortexLink = { fg = "#3e8fb0" } }
        highlights = {
          preset = nil,
          groups = {},
        },

        -- Link preview float (<prefix>K / :ZortexLinkPreview)
        preview = {
          on_hover = false, -- preview the link under the cursor on CursorHold ('updatetime' is the delay)
        },

        -- :ZortexPlan (ui/planner.lua, services/planner.lua)
        planner = {
          todo_link = "P/#TODOs", -- tasks under this project rank higher
          max_tasks = 30,
          project_tasks = 3, -- P puts a project's next this many open tasks on the day (5P: five)
          -- "Coming up": the events of this many days after the day (timed
          -- lines, @event, calendar notes), in the plan and the calendar
          -- view; 0 hides them
          upcoming_days = 7,
          -- The capacity line: open tasks on the day (their @size hours) against
          -- the free time left in `day`, after timed entries that aren't project
          -- work (lectures, appointments; one without an end counts event_minutes)
          capacity = {
            day = { "08:00", "22:00" },
            event_minutes = 30,
          },
          width = 70, -- plan window width
          advance = false, -- after a put, move the calendar cursor to the next line
          -- :ZortexPlan for today copies the open tasks of the days before

          carry_forward = true,
          carry_days = 14,
          -- Lines for a new calendar day: the calendar note's # Templates
          -- section (Weekday:, Sunday:, … labels; see services/calendar_rules)
        },

        search = {
          default_mode = "section", -- or "article", "text" (plain text); keys.cycle_mode cycles them
          max_results = 500,
          -- Keys in the search picker (any backend), shown in its title;
          -- false turns one off. <M-t> is taken by some terminals and
          -- multiplexers (zellij): e.g. cycle_mode = "<M-m>". Not <C-t>:
          -- telescope, snacks and fzf-lua open in a tab with it.
          keys = {
            cycle_mode = "<M-t>", -- section / article / text search
            new_note = "<C-o>", -- a new note named after the query

          access_decay_rate = 0.1, -- per day
          history = {
            enabled = true,
            max_entries = 50,
            score_decay = 0.1, -- per day
            propagation_decay = 0.7,
          },
          token_filters = {
            [1] = {
              constants.SECTION_TYPE.ARTICLE,
              { constants.SECTION_TYPE.HEADING, max_level = 1 },
            },
            [2] = {
              constants.SECTION_TYPE.ARTICLE,
              { constants.SECTION_TYPE.HEADING, max_level = 3 },
            },
            [3] = {
              constants.SECTION_TYPE.ARTICLE,
              constants.SECTION_TYPE.HEADING,
              constants.SECTION_TYPE.BOLD_HEADING,
              constants.SECTION_TYPE.LABEL,
            },
            [4] = "all", -- All section types except tags
          },
        },

        calendar = {
          window = {
            relative = "editor",
            width = 82,

            title = " 📅 Zortex Calendar ",
            title_pos = "center",
          },

            has_entry = "DiagnosticInfo",
            header = "Title",
            border = "FloatBorder",
            footer = "Comment",
            key_hint = "NonText",
            day_header = "Title",
            notification = "DiagnosticWarn",
            selected = "PmenuSel",
            today_selected = "PmenuSel",
            selected_text = "PmenuSel",
            selected_icon = "PmenuSel",
          },
          pretty_attributes = true, -- Enable/disable pretty display of attributes
          -- Plain Unicode by default; with a Nerd Font, e.g.
          --   event = "󰃰", task = "󰄬", task_done = "󰄱", notification = "󰂞", has_items = "󰸞"
          icons = {
            event = "◆",
            task = "□",
            task_done = "☑",
            notification = "!",
            has_items = "•",
            none = " ",
          },
          keymaps = {
            close = { "q", "<Esc>", "<C-c>" },
            next_day = { "l", "<Right>" },
            prev_day = { "h", "<Left>" },
            next_week = { "j", "<Down>" },

            add_entry = { "a", "i" },
            view_entries = { "<CR>", "o" },
            search = { "/" },

            go_to_file = { "gf" },

6. LUA API                                                        *zortex-api*

`require("zortex")` is the API; services load on first use: >lua
    local z = require("zortex")
    z.actions.review()                -- any action by id
    z.run("review", { args = "14" })  -- with command-style arguments
    z.query.search("1.4 zortex")      -- plain data, JSON-safe
    z.projects.resolve("[P/#1.4 - zortex]"):rollup()
    z.links.resolve_first("[A/#1 Personal]")
<
See README.md (Lua API) for the full list.

7. SERVER                                                      *zortex-server*

`zortex serve` (Go, one binary) reads the notes folder: rendered notes,
search, backlinks, the calendar's notifications (through ntfy), the
pomodoro, timers, alarms, a stopwatch and time tracking (`@spent`). The
plugin expects it running, locally or elsewhere: notifications, the
pomodoro and the alerts Neovim shows come from it. Its address: >lua
    require("zortex").setup({
      server = { api_endpoint = "https://zortex.example.com", api_key = "…" },
    })
<
`server = { enabled = false }` leaves it out; the notes, links, projects,
planning and XP work without it.
doc/Server.md in the repository covers Docker, NixOS, a proxy with a login
and ntfy.
